# AURA Firestore Indexes

This document tracks the Firestore indexes needed by AURA production AI surfaces.

## Deploy Existing Composite Indexes

The repo currently defines composite indexes in `firestore.indexes.json`.

Deploy them with:

```sh
firebase deploy --only firestore:indexes
```

Verify deployed indexes in Firebase Console:

```text
Firestore Database > Indexes > Composite
```

## Required AURA Query Areas

### Closet Items

Path:

```text
users/{uid}/items
```

Current composite indexes cover:

- `status ASC, createdAt DESC`
- `status ASC, wearCountSinceWash DESC`
- `category ASC, createdAt DESC`
- `category ASC, wearCountSinceWash DESC`
- `status ASC, category ASC, createdAt DESC`
- `status ASC, category ASC, wearCountSinceWash DESC`

Vector index needed:

- `items.embeddingVector`
- dimension: `2048`

### Style Memories

Path:

```text
users/{uid}/styleMemories
```

Vector index needed:

- `styleMemories.embeddingVector`
- dimension: `2048`

### Saved Outfits

Path:

```text
users/{uid}/savedOutfits
```

Production list query:

- `savedAtMs DESC`

Single-field descending indexes are normally automatic. If Firebase reports an index error for this query, create the console-suggested index and add it to `firestore.indexes.json` if supported.

### Calendar Outfits

Path:

```text
users/{uid}/outfits
```

Current calendar reads are document reads by `dateKey`, so no composite index is required for the main planner screen.

If a future list view queries by fields such as `plannedOutfit.source`, `plannedOutfit.createdAt`, `wornOutfit.wornAt`, or date ranges, add the exact composite index from the Firestore missing-index error.

## Vector Index Creation

Vector indexes are not represented in the current `firestore.indexes.json`.

Use one of these production-safe approaches:

1. Run the agent/retrieval path in a staging project and use the Firestore missing-index link to create the exact vector index.
2. Create the vector index from Firebase Console for `embeddingVector` with dimension `2048`.
3. If using `gcloud`, use the command generated by the current Firestore missing-index error for the project. Do not paste a hand-written command into production unless it has been verified against the installed `gcloud` version.

## Missing Index Symptoms

Common production symptoms:

- Agent returns a friendly wardrobe-intelligence-updating or try-again message.
- Firebase logs include `FAILED_PRECONDITION`.
- Error mentions a missing index or vector index.
- Retrieval returns no candidates even when indexed items exist.

When this happens:

1. Confirm the project and environment are correct.
2. Open the missing-index link from Firebase logs if present.
3. Create the index in staging first.
4. Re-run:

```sh
cd functions
npm run eval:aura:gate
```

5. Run the manual AURA QA checklist.
